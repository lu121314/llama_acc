# 网页 UI 使用说明

先进入正在使用的工程目录。下文以 `llama32_3b_zu7cg_pynq_v1` 为例；两套 `llama32_3b_ctx8192_*` 独立工程使用相同界面，其硬件、模型与上下文参数各自保留。

## 从 Jupyter 终端启动

在板卡的 Jupyter **终端**复制以下一整行执行：

```bash
cd /home/xilinx/jupyter_notebooks/llama32_3b_zu7cg_pynq_v1 && bash run.sh --mode ui
```

服务启动成功后，终端会打印板卡的 HTTP 访问地址。点击链接打开网页；部分 Jupyter 版本需要 `Ctrl+单击`，也可复制地址到浏览器。示例 `http://192.168.2.99:8088/` 中的 IP 以终端实际打印值为准，不使用 HTTPS。

服务在前台运行，请保持启动终端打开。按 `Ctrl+C` 停止服务；更新工程后重新启动，旧页面刷新一次即可加载新界面。服务打印访问地址前，会先在主线程发现 PYNQ 设备；此时不下载 Overlay 或上传权重，进入网页后点击“初始化模型”。

`bash run_ui.sh` 也可启动界面，并将服务终端输出保存到 `logs/ui/`。需要修改端口时使用 `bash run.sh --mode ui --port 8090`。`bash run.sh --mode ui --demo` 为模拟预览，页面会明确标注演示数据，不访问 FPGA 或模型文件。

在 Jupyter 内显示界面，可打开 `notebooks/网页UI.ipynb` 并运行嵌入单元。它连接已启动的同一服务，不创建第二个推理进程。若 Jupyter 通过 HTTPS 打开，浏览器可能阻止嵌入 HTTP 页面，此时直接点击终端中的地址，在新标签页使用网页。

## 选择上下文和时钟

初始化前在顶部选择组合，选项同时显示上下文容量和时钟，例如 `1024 context · 187.5 MHz` 或 `8192 context · 250 MHz`。最大输出控件及上下文指标随所选组合更新。切换到较小上下文时，已有最大输出若超限会降到该上限；显式输入超限值仍会提示修改。

8K 选项保留用于后续硬件交付。缺少该组合的 bit、HWH 或 manifest 时，选项会标注“硬件尚未交付”，初始化按钮禁用；配置中的频率只标为预设，不表示已测得运行时钟。系统不会回退加载 1K 硬件。补齐该组合的三件套及 8K 双核镜像后，重启服务再检查和初始化。

1K 与 8K 需要各自配套的模型镜像；输入、历史及预留输出共享所选硬件的总上下文。已初始化时不能直接更换组合，需先清除 bit。完整文件路径和同型号新板部署步骤见 [新板卡部署指南](docs/新板卡部署指南.md)。

## 界面与键盘操作

顶部为加速器状态、实际时钟、首 token 延迟、推理耗时、解码及总体 token/s、输入/输出数量、停止原因和上下文上限。权重进度条显示双 DDR 累计字节数、百分比、MiB/s 和耗时。左侧显示对话，右侧显示日志。

日常模式仅上传权重，不进行权重哈希或 DDR 回读校验。文件大小、内存预留与 bit/HWH 配套检查继续保留。需要详细上板诊断时使用 `test/` 中的脚本。

| 按键 | 操作 |
|---|---|
| F2 | 聚焦提示词 |
| Enter / Shift+Enter | 发送 / 换行；中文输入法组词时不会误发 |
| F4 | 初始化硬件并上传权重 |
| F6 | 开始新对话，保留已加载模型 |
| F8 | 打开清除 bit 确认，Enter 确认，Esc 取消 |
| F10 | 聚焦日志；Ctrl+A 全选日志，Ctrl+C 复制 |
| Tab / Shift+Tab | 前后切换控件；方向键调节选择框和数字 |

多个浏览器连接同一服务时，约每 250 ms 同步对话、设置、运行状态、进度和日志；未发送草稿约 150 ms 提交同步。键盘焦点、文本选择、滚动位置和尚未提交的确认框属于本地浏览器。

上传或推理期间所有页面都会显示忙碌，不能同时发起另一个硬件操作。完成后可从任意页面输入。Chat 沿用当前加速器每轮软复位、重新处理完整历史的流程。改变模式或系统提示词会清空对话；最大输出与输入、历史共同占用当前工程的总上下文预算。

## 重演启动过程

1. 推理完成后点击“清除 bit”或按 F8，并确认操作。
2. 服务下载同器件的独立空闲 bit，移除加速器，网页回到待初始化状态。
3. 如需更换硬件版本，在版本框中选择；各工程只显示其配置提供的硬件。
4. 点击“初始化模型”或按 F4，重新演示 Overlay 下载和双 DDR 权重上传。

清除不会删除或覆盖加速器 bit/HWH、模型文件，也不会擦除所有 DDR 内容；PL 处于空闲配置。它不用于硬件超时后的强制恢复。相关 API 使用依据见 [PYNQ Bitstream](https://github.com/Xilinx/PYNQ/blob/master/pynq/bitstream.py) 和 [EmbeddedDevice.download](https://github.com/Xilinx/PYNQ/blob/master/pynq/pl_server/embedded_device.py)。

磁盘日志保存在 `logs/ui/`。本机模拟验证不能替代板端实际推理及空闲 bit 下载验证。
